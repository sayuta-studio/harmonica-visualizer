# プロジェクト固有トラブルシューティング（2割の固有知見）

※ 本プロジェクト特有のロジックや仕様に起因するエラーと対処法を記録。

## 1. 外部音源のミリ秒同期と「先頭巻き戻し」フリーズ
- **発生事象**: 外部伴奏（MP3/WAV）再生中に巻き戻し（先頭ボタン）を押すとGUIがハングアップする。また正のオフセット（遅延発音）が機能しない。
- **原因**:
  - `pygame.mixer.music` のストリーミング再生ではミリ秒単位のシーク精度が出ず、負の秒数を指定できないため発音待機が制御できない。
  - ハンドラ内でロック競合が発生していた。
- **対処・回避策**:
  - ロード時に音声データを 44.1kHz / 16bit / Stereo の NumPy 配列としてメモリに展開（PCMスライス再生）。
  - `src_sec >= 0` の場合はインデックス計算で配列をスライスして `pygame.sndarray.make_sound()` で即座に発音（0.02ms精度）。
  - 遅延待機時はフラグ管理で楽曲時間がオフセットに達した瞬間に発音開始。巻き戻し時は専用チャンネルの `.stop()` と内部クロックのリセットをシーケンス実行。

## 2. マイク録音の前奏（カウントイン）混入と動画出力時の頭ズレ
- **発生事象**: カウントイン（1〜2小節の前奏）を設けて録音すると、動画書き出し時に演奏と動画が前奏秒数分だけズレてしまう。
- **原因**: 録音WAVの先頭に前奏分の無音やブレスが含まれる一方、動画は本編0.0秒から始まるため。
- **対処・回避策**:
  - 録音停止時に前奏秒数分をサンプル境界バイトトリムで自動切断：
    ```python
    frame_bytes = channels * 2  # 16-bit PCM = 2 bytes per sample
    trim_frames = int(round(trim_start_sec * sample_rate))
    trim_bytes = trim_frames * frame_bytes
    buffer = buffer[trim_bytes:]
    ```
  - これにより保存されるWAVデータは常に楽曲本編0.0秒ジャストに頭出しされる。

## 3. 和音の単音化フィルターとハーモニカ異名同音（変え指）の階層解決
- **発生事象**: ピアノ譜などのMIDI読み込み時に和音が含まれて複数の穴が同時に光る。また奏者の好みに応じた異名同音（変え指）の切り替えが必要。
- **原因**: MIDIデータ上の重なりノーツと、楽器固有の複数演奏パターンの競合。
- **対処・回避策**:
  - 微小Tick窓による重なりノーツ検出と「高音優先（メロディ）/低音優先」の単音化フィルター（非優先ノーツを `is_muted` 化）。
  - 3階層運指解決システム：
    1. Layer 1（最優先）: ユーザーによる個別オーバーライド（`(tick, pitch) -> candidate_idx`）
    2. Layer 2（中優先）: 曲全体の運指プリセット（スライド最小化、吹吸統一等）
    3. Layer 3（基底）: 楽器モデル基本運指テーブル

## 4. マルチトラック合成とYouTubeラウドネス規格（ITU-R BS.1770）
- **発生事象**: 外部伴奏・マイク録音・シンセ音を多重合成して書き出すと、合計振幅が 0 dBFS を超えて激しいデジタルクリッピング（音割れ）が発生する。
- **原因**: 複数トラックの波形加算による振幅オーバーフロー。
- **対処・回避策**:
  - 合成後に ITU-R BS.1770 準拠のラウドネス解析（目標 `-14.0 LUFS`）を実施。
  - True Peak を `-1.0 dBFS`（振幅上限 `0.891`）にクランプするソフトニーリミッターを最終段に適用。
