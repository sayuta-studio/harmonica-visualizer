# 知見の仕分け基準（8割の汎用知見 vs 2割の固有知見）

## 1. 8割の汎用知見（shared_knowledge/ 配下へ）
他のソフトウェア開発でも再発しそうな知見は、汎用知見として記録する。
※ 一般的な言語仕様や教科書的知識は記録せず、「AIが油断すると踏み抜く落とし穴（Gotchas）」に特化すること。
- **ui_ux.md**: レイアウト崩れ防止、レスポンシブ、イベントループのブロッキング回避、再描画の最適化など。
- **env_build.md**: パッケージング（PyInstaller等）のトラブル、依存関係衝突、OS固有のパスや権限問題など。
- **architecture_patterns.md**: デッドロック対策、非同期処理の注意点、設定ファイル管理パターンなど。

## 2. 2割のプロジェクト固有知見（.context/03_troubleshooting.md へ）
- 特定アプリ固有のビジネスロジックや計算式に関する不具合。
- このプロジェクトでのみ使用している特殊なデータフォーマットや固有仕様のバグ。
