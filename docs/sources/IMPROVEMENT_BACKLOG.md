### 【課題 1】カウントイン（前奏）の「1拍目の音」が鳴らない
* **現象**: 
  * 再生開始時、カウントインの1拍目のクリック音が聞こえず、3拍分だけ鳴った直後に曲（本編）に入ってしまう。
  * 最初の1拍目が欠落するため、テンポ感を掴む前に演奏が始まってしまい演奏に入りづらい。
* **原因分析・技術メモ**:
  * 開始直後（t = 0.0s）のオーディオデバイス初期化遅延・バッファ立ち上がりレイテンシにより、第1拍目のイベントがスキップまたは無音扱いされている可能性。
  * タイミング生成時に `t = 0` の発音をミリ秒単位でわずかに先行ロードするか、WinMMの初弾クリック発音タイミングを安全マージン（数ミリ秒先行）でキックする調整が必要。
* **対応方針**:
  * 1拍目の「カンッ（高音）」が確実に耳に届くよう、初期化順と発音トリガーの余裕を持たせる。

### 【課題 2】A-Bループの周回時にカウントイン（予備拍）が鳴らない
* **現象**:
  * A-Bループ練習中、B点に到達してA点へ巻き戻った瞬間にカウントインがなく、即座にA点の演奏音が鳴り始めてしまう。
  * 息継ぎや準備をする間がなく「尻切れ」のようになってしまい、反復練習がやりづらい。
* **v2.1の仕様確認**:
  * v2.1ではループ末尾に到達した際、A点へ巻き戻ると同時に設定されたカウントイン（1小節または2小節）が再度カウントされてからA点の演奏に入っていた。
* **原因分析・技術メモ**:
  * `v3.0` のループ巻き戻しロジックが `self.clock.seek(self.loop_a_sec)` を直接呼んでおり、再生状態を `count_in` フェーズに戻さず本編時間へ直行している。
* **対応方針**:
  * B点到達時の巻き戻し処理に「カウントインが設定されている場合は、A点の直前に予備カウントイン小節を挿入して再同期する」ロジックを追加し、v2.1同様に呼吸を整えてから練習に入れるようにする。

### 【課題 3】動画書き出し実行時にエラー表示なしでアプリが落ちる（クラッシュ）
* **現象**: 
  * 「🎬 動画出力」タブから動画書き出しを実行した瞬間、エラーダイアログやトレースバックが出ずにアプリケーションが突然終了（強制終了）する。
* **原因分析・技術特定（判明！）**:
  1. **直接原因 1（ダイアログ起動時の未定義エラー）**:
     * `v3.0/dialogs.py` 内で `import os` がインポートされておらず、書き出し進捗ダイアログ（`ExportProgressDialog`）の初期化コード（1059行目: `os.path.basename(...)`）が呼ばれた瞬間に `NameError: name 'os' is not defined` が発生。
  2. **直接原因 2（バックグラウンドスレッド側の未定義エラー）**:
     * `v3.0/video_exporter.py` 内で `import threading` がインポートされておらず、1052行目の `threading.Thread(...)`（FFmpegのstderrドレイン用スレッド）で `NameError: name 'threading' is not defined` が発生。
  3. **「エラーを吐かずに落ちた」理由**:
     * スタンドアローンEXEが `--noconsole`（GUIウィンドウ専用）モードでビルドされているため、コンソール画面（黒い画面）が存在せず、Pythonの未捕捉例外（NameError）のメッセージが表示される前にWindowsによってプロセスごと即時終了させられたため。
* **対応方針**:
  * `v3.0/dialogs.py` の冒頭に `import os` を追加。
  * `v3.0/video_exporter.py` の冒頭に `import threading` を追加。
  * 合わせて、書き出し時の未捕捉例外を安全にGUIの `QMessageBox` で通知するクラッシュセーフガード（大域的例外トラップ）を配備。

### 【課題 5】背景画像「横幅に合わせる」時の上下枠外へのはみ出し（クリッピング漏れ）
* **現象（スクショ確認済み）**:
  * 4:3等の縦長・正方形に近い画像を背景に設定し、配置「横幅に合わせる」を選択した際、本来は16:9キャンバスの上下枠でトリミング（カット）されるべき画像が、練習画面のキャンバス枠（黒帯マージン領域）の上側や下側にまで飛び出して描画されてしまう。
* **原因分析・技術特定（判明！）**:
  * `v3.0/gl_visualizer.py`（678行目付近）の描画処理で、拡大後の画像高さ `new_h` がキャンバス有効高さ `disp_h` を超えた際、描画領域を `dest_rect`（16:9の表示矩形）でクリッピング（切り抜きマスク）していないため、画面の上下余白領域にそのまま描画が漏れ出ている。
* **対応方針**:
  * 背景画像の描画処理の直前に `p.save()` ➔ `p.setClipRect(dest_rect)` を設定し、キャンバス矩形外への描画を強制クリップ（はみ出し禁止）する。描画完了後に `p.restore()` で復元。
  * これにより、4:3画像でも16:9キャンバスの内側だけに綺麗に上下がトリミングされて収まるようになる。

### 【課題 7】マイク録音テイク試聴時のリバーブ再生成・リアルタイム反映（キャッシュ固定バグの解消）
* **現象・ご要望**:
  * マイク録音後、「リバーブを適用」の深さ（％）やタイプを変更しても試聴音に反映されず、調整しながら聴き比べができない。
  * 試聴ボタンを押すたびに現在のリバーブ設定で最新の音声を生成するか、スライダー操作時にリアルタイムでリバーブのかかり具合を聞きながら微調整できるようにしたい。
* **原因分析・技術特定（判明！）**:

* **対応方針**:
  * **試聴ボタン押下時**: 現在のスライダー深さ％・空間タイプに基づいて常に最新の `_reverb.wav` を即時上書き生成（NumPy処理はわずか約0.05秒で完了するため待たされません）。
  * **スライダー調整時**: 試聴再生中に深さスライダーを動かした場合、即座にリバーブを再適用してシームレスに再生を更新し、耳で残響を確認しながら直感的にスライダーを合わせられるリアルタイム体験を実装する。

### 【動画課題 1】書き出し動画内で本編メトロノームと曲（ノーツ）の頭拍がズレる
* **ステータス**: 原因特定完了・記録済み（後ほど一括対応予定）
* **現象**: 
  * 出力されたMP4動画を再生すると、メトロノームのクリック音と曲のノーツ（特に頭の拍）の発音タイミングがズレている。
* **原因分析・コード検証結果（特定完了！）**:
  * `v3.0/audio_engine.py` の `synthesize_midi_to_wav()` 内（1326〜1340行目）において、本編メトロノームのクリック音合成時刻を計算する際：
    ```python
    if m_base_time is not None:
        sec_per_tick = 60.0 / (max(1.0, current_bpm) * ticks_per_beat)

    ```
    ノーツ側の発音開始時刻（1371行目）：
    ```python
    start_in_video = intro_sec + count_in_duration + (start - sec_a_in_song)
    ```
    と比較して、メトロノーム側の計算式に **`intro_sec + count_in_duration - sec_a_in_song` の時間オフセットが完全に抜け落ちていた** ことが判明。

* **改修方針**:
  * メトロノームの各拍時刻計算に `intro_sec + count_in_duration + (m_base_time - sec_a_in_song)` を適用し、ノーツのタイムラインと1サンプル単位で完全同期させる。
  * また、`video_exporter.py` から `self.timeline.tick_to_sec` も渡せるようにし、テンポチェンジがある楽曲でも各拍の頭が100%一致するように統一する。

### 【動画課題 2】動画書き出しダイアログの「保存フォルダを開く」が保存先ではなくドキュメントを開いてしまう
* **ステータス**: 原因特定完了・記録済み（後ほど一括対応予定）
* **現象**: 
  * 動画書き出し中・完了時に進捗ダイアログの「📂 保存フォルダを開く」ボタンを押すと、指定した保存先フォルダ（`output/` など）ではなくWindowsの「ドキュメント」フォルダが開いてしまう。
* **原因分析・コード検証結果（特定完了！）**:
  * `v3.0/dialogs.py` の `ExportProgressDialog._open_folder()`（1408行目）において：
    ```python
    folder = os.path.dirname(self.output_path)
    subprocess.Popen(f'explorer "{folder}"')
    ```
  * `self.output_path` は `QFileDialog.getSaveFileName()` で取得されるため、Qtの仕様でパス区切りがスラッシュ（`/`）になっています（例: `C:/Users/.../output/video.mp4`）。

* **改修方針**:
  * `os.path.normpath()` でWindows標準のバックスラッシュ（`\`）へ正規化。
  * さらに、動画ファイルが生成済みの場合は `explorer /select,"{norm_path}"` で該当MP4ファイルを自動フォーカス・選択した状態でフォルダを開く、より親切な挙動へ改修する。

### 【動画課題 6】完全背景透過MOVの設定見直し（PNG ➔ 業界標準 ProRes 4444 / QTRLEへの刷新）およびキャンセル時の破損ファイルクリーンアップ
* **ステータス**: 原因・仕様確定・記録済み（後ほど一括対応予定）
* **現象・ユーザーからの報告**:

     * 現在のコードでは `ffmpeg -c:v png -pix_fmt rgba output.mov`（QuickTime PNG）が指定されていますが、QuickTime PNGは**汎用的な動画フレームワーク（OpenCVやWindows Media Foundation、多くの最新動画ツール）で `codec not found (id=61)` となり未対応**です。
     * 動画編集・配信ソフト（Adobe Premiere Pro, After Effects, DaVinci Resolve, Final Cut Pro, OBS, AviUtl等）で背景透過素材として使われる**世界標準のデファクトスタンダードは Apple ProRes 4444（`-c:v prores_ks -profile:v 4444 -pix_fmt yuva444p10le`）** です。
  3. **中断・キャンセル時の不完全ファイル残存（実破損）**:
     * 該当ファイル（`紅楼 ～ Eastern Dream.mov`）のバイナリを精査したところ、末尾のインデックス情報 `moov atom` が存在せず（Size 0のまま中断）、実際に破損していました。
     * 書き出し途中でキャンセルボタンを押したり、ウィンドウを閉じた際に、書きかけの不完全なMOVファイルがディスク上にそのまま残ってしまう不備が判明しました。
* **改修方針**:
  * **1. 業界標準コーデック Apple ProRes 4444 への刷新**:
    * `video_exporter.py` の透過MOVエンコード設定を、Premiere Pro, DaVinci Resolve, After Effects, Final Cut Pro, AviUtl, OBS等でネイティブに透過合成できる **Apple ProRes 4444（`-c:v prores_ks -profile:v 4444 -pix_fmt yuva444p10le`）** に刷新します。
  * **2. キャンセル・異常終了時の安全なクリーンアップ**:
    * 書き出し中断時（`_is_cancelled`）やエラー発生時に、生成途中の壊れた未完成ファイルを `os.remove()` で確実に自動消去し、ゴミファイルが残らないようにします。
  * **3. UIでの親切なガイド表示**:
    * タブ4「動画出力」のスタイル選択時および書き出し完了ダイアログに、「※完全透過MOVは動画編集ソフト（Premiere, DaVinci, AviUtl, OBS等）で重ねて使う合成用素材です（Windows標準プレイヤー単体では再生できません）」との案内を付記し、ユーザーが迷わないようにします。

### 【課題 25】伴奏・外部音源モードの全項目総点検 ＆ UX全面刷新（無音バグ・再生漏れバグの完全根絶）
* **ステータス**: 原因全解明・仕様確定・記録済み（後ほど一括対応予定）
* **現象・ユーザーからのご指摘**:
  * 伴奏・外部音源のモードがわかりにくく、意図した挙動になっていない。
  * 「外部音源のみ」にすると完全な無音になってしまう。
  * 逆に「ガイド音のみ」にしても、読み込んだ外部音源の音が鳴り続けてしまう。
  * 全項目を確認して仕様を正してほしい。
* **全項目コード検証結果（原因完全特定！）**:
  1. **「外部音源のみ」で無音になる原因**:
     * `_on_ext_mode_changed` で `audio_engine.set_muted(True)` を呼び出しているが、これにより **カウントインのメトロノームクリック音まで完全消音** されてしまっていた。
     * カウントイン中（例: 2小節＝約4秒間）、メトロノームが鳴らず外部音源も開始秒前のため、再生ボタンを押しても4秒間「完全な無音」となりフリーズしたように誤認させていた。
  2. **「ガイド音のみ」で外部音源が鳴り続ける原因**:
     * コンボボックスを「外部音源オフ (ガイド音のみ)」に切り替えた瞬間、すでに再生中の `pygame.mixer.music` を即座に停止（`stop()`）する処理が `_on_ext_mode_changed` 内で完全に抜け落ちていた。
     * また、試聴ボタン（`▶ 試聴`）でもモード判定を無視して無条件に外部音をロード・再生していた。
  3. **モードの命名・役割の混乱（再生と動画の混同）**:
     * タブ3（日々の練習タブ）なのに「頭出し確認 (再生:両方 / 動画:外部のみ)」のように動画の話が混ざっており、タブ4（動画出力タブ）の「音声ソース」設定と役割が衝突して極めて分かりにくくなっていた。
* **改修方針（直感的で迷わない3択への整理 ＆ バグ完全根絶）**:
  1. **タブ3のモードを「再生時のスピーカー出力3択」へ完全整理**:
     * `🎵 伴奏再生モード:`
       - **`伴奏 ＋ ガイド音 (両方再生)`**【標準：タイミング確認・耳合わせ用】
       - **`伴奏のみ (ガイド音オフ)`**【カラオケ練習用：メトロノームカウントインは生かし、MIDIノートのみ消音】
       - **`ガイド音のみ (伴奏ミュート)`**【単独練習用：外部音源を即座に完全停止・ミュート】
  2. **カウントイン（メトロノーム音）の独立防衛**:
     * 「伴奏のみ」モード時、MIDIノート発音は消音するが、**メトロノーム拍・カウントイン音はミュートせず確実に発音**させ、無音待機による混乱を根絶する。
  3. **切り替え時の即時反映**:
     * コンボボックス切り替え時に、現在の再生状態に合わせて即座に `pygame.mixer.music.stop()` またはミュート切り替えを反映。
  4. **動画への音声合成はタブ4に一本化**:
     * 動画出力時にどの音声を合成するかは、タブ4「🎬 動画出力」の「音声ソース」設定で明確に完結させる。

### 【動画課題 9】タイトル・クレジット文字列が長い場合に枠からはみ出ない文字サイズの自動縮小（Auto-fit Font Scaling）
* **ステータス**: 原因特定完了・仕様策定・記録済み（後ほど一括対応予定）
* **現象・ユーザーからのご要望**:
  * 動画出力（または静止画プレビュー）において、楽曲名や演奏者・クレジットの文字列が長い場合、タイトルカード枠（背景プレート）を突き抜けて左右にはみ出してしまう。
  * 枠を超える場合は、枠内に美しく収まるように文字サイズ（フォントサイズ）を自動調整（縮小）してほしい。
* **原因分析・コード検証結果（特定完了！）**:
  * `v3.0/video_exporter.py` の `_draw_title_overlay()`（810〜875行目）において：
    1. タイトルカードの枠幅 `card_w` は上限クランプ（イントロ中央は画面幅の88%＝`w * 0.88`、左上・右上常時は画面幅の45%＝`w * 0.45`）が設定されている。
    2. しかし描画フォントは固定サイズ（イントロタイトル: `28.0 * scale`、イントロクレジット: `15.0 * scale`、常時タイトル: `13.0 * scale`、常時クレジット: `10.0 * scale`）で一律に指定されていた。
    3. カード幅の算出にも `len(text) * 26.0` という粗い文字数推定が使われていたため、日本語（全角）やサブタイトルを含む長い楽曲名・演奏者名を入力した際、実際のテキスト横幅がカード枠の許容幅を容易に突破し、左右の枠外へ文字が溢れ出てしまっていた。
* **改修仕様（自動フォントフィッティング機能の実装）**:
  1. **`QFontMetricsF` による精密テキスト幅計測**:
     - 簡易な文字数カウント（`len()`）を廃止し、`QFontMetricsF(font).horizontalAdvance(text)` を用いて日本語・英数・記号が混ざった文字列の実寸ピクセル幅を正確に測定。
     - カード枠幅もこの実測幅に合わせて自然にフィット（適切な左右余白を維持）。
  2. **自動縮小ヘルパー（`_fit_font`）の導入**:
     - カード描画可能幅（`avail_w = card_w - padding`）に対してテキスト幅が超えている場合、`ratio = avail_w / text_w` を計算し、`font.setPointSizeF(base_pt * ratio * 0.98)` で枠内に100%収まるよう文字サイズを自動ダウンサイジング。
     - 極端な潰れを防止する安全下限値（イントロ 9pt、常時 6pt）を担保。
  3. **静止画プレビュー＆動画本編の両方に即時反映**:
     - `_draw_title_overlay` 共通処理を改修するため、動画出力本編だけでなくタブ4の「📸 静止画プレビュー」でも枠内に綺麗に収まったタイトルカードが確認可能。
